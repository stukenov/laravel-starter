## 1. Назначение

Основа для новых проектов. Клонируется, переименовывается, получает новый remote — и на ней сразу можно писать функционал, не тратя день на авторизацию, роли, локали и оформление.

Ключевое требование: **никакого демонстрационного содержимого Laravel**. Всё, что есть в стартере, — рабочий функционал, который останется в проекте.

## 3. Окружение разработки

Всё нативно, **без Docker**.

## 4. База данных

**Только PostgreSQL.** Приложение падает на старте с внятной ошибкой, если драйвер подключения не `pgsql`. Проверка живёт в сервис-провайдере — чтобы никто случайно не запустил проект на SQLite и не поймал тихие расхождения.

### Используемые возможности Postgres

| Возможность | Где применяется |
|---|---|
| `uuidv7()` — встроена в PG 18, расширение не нужно | Первичные ключи всех таблиц. Значение по умолчанию задаётся на уровне базы |
| `citext` | Колонка `users.email` — уникальность без учёта регистра без костылей в коде |
| `timestamptz` | Все временные колонки без исключений |
| Генерируемая колонка `tsvector` (STORED) + GIN | Поиск по пользователям в панели |
| `pg_trgm` + GIN | Поиск по подстроке в имени — дополняет полнотекстовый |
| `jsonb` + GIN | Журнал действий: свойства записи |
| Частичные индексы | Только активные сессии |
| `LISTEN` / `NOTIFY` | Транспорт для живых обновлений (раздел 13) |

Очереди, кэш и сессии — **в Postgres**. Redis не используется.

## 5. Время

- `config/app.php` → `timezone` = `UTC`. В базе всё хранится в UTC.
- У пользователя поле `timezone`, по умолчанию `Asia/Almaty`. Значение проверяется по списку `DateTimeZone::listIdentifiers()`.
- Сервер всегда отдаёт время в ISO 8601 (UTC).
- Форматирование — на клиенте через встроенный `Intl.DateTimeFormat` с таймзоной из свойств страницы. Никаких `dayjs`, `moment`, `date-fns`.

Правило: **в интерфейсе не должно быть ни одной даты, отрисованной сервером в готовом виде.** Сервер отдаёт момент времени, клиент решает, как его показать.

## 6. Локализация

Три языка: **русский, казахский, английский**.

**Гибридная схема адресов:**
- Публичная часть — с префиксом: `/ru/...`, `/kk/...`, `/en/...`. Корень `/` перенаправляет по языку браузера.

На публичных страницах проставляются теги `hreflang`.

## 8. Страницы ошибок

Заказчику не нравится, что Inertia показывает ошибку модальным окном поверх страницы. Причина: когда сервер отвечает не-Inertia-ответом, клиент по умолчанию выводит его во всплывающем окне.

**Решение в три слоя:**

1. Обработчик исключений в `bootstrap/app.php` для Inertia-запросов отдаёт `Inertia::render('errors/ErrorPage')` — обычную страницу приложения. Модальное окно отключается явной настройкой клиента.
2. **Blade-запасной вариант** в `resources/views/errors/*.blade.php` — со встроенными стилями и тем же шрифтом. Он обязателен: если процесс SSR упал, страницу 500 через Inertia отрисовать физически нечем.
3. Ошибка 419 (сессия истекла) — **не страница ошибки**, а перенаправление на вход с понятным сообщением. Иначе пользователь видит «Page Expired» и не понимает, что делать.

Покрываются: 403, 404, 419, 429, 500, 503.

## 9. Авторизация

Контроллеры пишутся свои — чтобы страницы были полностью нашими. Fortify и Breeze не используются.

**В составе:**
- вход и выход;
- регистрация — работает, но **выключается флагом** `REGISTRATION_ENABLED=false`, который убирает и маршрут, и ссылку в интерфейсе;
- сброс пароля по почте;
- подтверждение адреса почты;
- подтверждение пароля перед опасными действиями;
- **сессии и устройства** — список активных сессий, «выйти со всех остальных устройств».

**Не входит:** двухфакторная аутентификация, вход через соцсети, вход по ссылке, Sanctum и API-токены.

Разбор строки user-agent для списка устройств — пакет `matomo/device-detector`.

Драйвер сессий — база данных (иначе список сессий невозможен).

Ограничение частоты запросов включено на входе, регистрации и сбросе пароля.

## 11. Панель `/dash`

Префикс `/dash` — и панель управления, и администрирование. Отдельного `/admin` нет.

```
/dash                    сводка
/dash/users              список пользователей с поиском
/dash/users/new          создание — модальное окно, форма короткая
/dash/users/:id          редактирование — модальное окно
/dash/roles              список ролей
/dash/roles/:id          матрица прав — отдельная страница, форма большая
/dash/permissions        список прав + модальное окно
/dash/audit              журнал действий, с живым обновлением
```

Настройки профиля — отдельными страницами:

```
/settings/profile        имя, почта
/settings/password       смена пароля
/settings/locale         язык и таймзона
/settings/sessions       устройства и сессии
/settings/delete         удаление аккаунта
```

**Правило разделения:** список — это список, создание и редактирование — отдельная страница или модальное окно. Ничего не сваливается на один маршрут. Выбор между страницей и окном определяется объёмом формы: короткая форма — окно, большая — страница.

Журнал действий ведётся пакетом `spatie/laravel-activitylog`, хранилище переводится на `jsonb` с индексом GIN.

## 13. Живые обновления

Механизм — **SSE поверх `LISTEN` / `NOTIFY`**. Проверено: в PHP доступны `pg_connect`, `pg_socket`, `pg_get_notify`.

**Как устроено:**
- Событие пишется в таблицу с порядковым номером, затем вызывается `pg_notify`.
- Обработчик SSE засыпает на `stream_select()` по сокету соединения и просыпается от уведомления. **Базу не опрашивает.**
- Соединение живёт около 25 секунд и закрывается. Браузерный `EventSource` переподключается сам и присылает заголовок `Last-Event-ID` — поток продолжается ровно с места обрыва по порядковому номеру.

Так решается главная проблема SSE на PHP-FPM: каждое открытое соединение занимает воркер, а здесь их число ограничено сверху временем жизни соединения.

**Два потребителя в стартере:**
1. Живой журнал действий на `/dash/audit` — записи появляются сами.
2. Мгновенная реакция на отзыв сессии — если сессию убили с другого устройства, вкладка выходит сразу, а не на следующем запросе.

Если однажды упрёмся в производительность — SSE выносится в отдельный процесс Node. Сессии лежат в Postgres, поэтому он проверит авторизацию сам, без дублирования логики. Это описывается в README, но не реализуется.

## 14. Безопасность

- **CSP** через `spatie/laravel-csp`, с nonce для встроенных скриптов Inertia. В режиме разработки — отдельная, более мягкая конфигурация для Vite.
- Заголовки: HSTS, X-Frame-Options, Referrer-Policy, Permissions-Policy, X-Content-Type-Options.
- Защита открытой регистрации от ботов — `spatie/laravel-honeypot`. **Капча от Google или Cloudflare исключена принципиально**: это чужой скрипт при отрисовке страницы.
- Ограничение частоты на всех формах авторизации.
- `roave/security-advisories` в зависимостях разработки — не даёт установить пакет с известной уязвимостью.
- Режим обслуживания с секретной ссылкой (`php artisan down --secret`) — чтобы во время развёртывания можно было зайти самому.

## 16. Тестирование

Три уровня, на каждом — три состояния данных.

**Уровни:**
1. **Бэкенд** — Pest: логика, сервисы, валидация, маршруты, права.
2. **Взаимодействие** — Playwright: настоящие клики, ввод, отправка форм, переходы, поверх живого SSR.
3. **Отрисовка данных** — Vitest и Testing Library: что реально показано — значения в полях, строки таблиц, счётчики, состояния кнопок.

**Состояния на каждом уровне:**
1. правильные данные — проходит как задумано;
2. неправильные — ошибки проверки, чужие и слишком длинные значения, отказ;
3. пустые — ноль записей, пустой ответ, `null`, пустое состояние экрана.

## 20. Вынесено за рамки: ИИ-агенты

Направление проработано, но **в основную ветку не входит**. Причина: схема не обкатана ни одним живым прогоном из PHP, а стартер — основа для всех будущих проектов.

Работа ведётся в отдельной ветке `feature/ai-agents`. Вливается только после того, как заработает и покроется тестами.

**Что уже выяснено и подтверждено проверкой:**

- Установлены четыре движка: `codex` 0.144.2, `claude` 2.1.220, `cursor-agent` 2026.07.09, `opencode` 1.17.11. Все умеют неинтерактивный режим, поток событий в JSON, продолжение сессии по идентификатору и выбор модели.
- Решено писать **свою обёртку** на `symfony/process` — он уже входит в состав Laravel.
- Готовый пакет `symfony/ai-codex-platform` изучен по исходникам и **не подходит**: промпт передаётся аргументом командной строки (виден в `ps aux`), продолжения сессии нет вовсе, карта флагов устарела, тянет за собой чужой слой абстракций версии до 1.0.
- Остальные найденные пакеты мертвы: `neosoftware/openai-codex-sdk` — ноль скачиваний, `gtgt/symfony-ai-cursor-platform` — три.
- Движки для реализации: **codex и cursor-agent**.
- Разделение по читателю: `AGENTS.md` в папке агента — для самого агента (кто он, что делает, чего не делает); `config/agents.php` — для приложения (движок, модель, таймаут, песочница, разрешённые MCP).
- Схемы ответа не используются. Два агента-примера: диалоговый с продолжением сессии и одноразовый без треда.
- Права в веб-контуре: только чтение плюс MCP по белому списку.
- Главная опасность: рабочая папка агента **обязана лежать вне корня приложения**, иначе инъекция в промпт открывает доступ к `.env` с паролем базы и ключом приложения.
- `laravel/mcp` — тоже в эту ветку. В основе у него не было бы потребителя.

Механизм SSE при этом **остаётся в основе** и обкатывается на журнале действий — чтобы к моменту внедрения агентов он уже был проверен.
