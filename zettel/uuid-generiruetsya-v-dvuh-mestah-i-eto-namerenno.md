# UUID генерируется в двух местах, и это намеренно

Сначала я сделал «чисто»: значение по умолчанию `uuidv7()` на уровне базы, а генерацию в модели отключил — пусть ключ выдаёт кто-то один.

Получилось хуже. Eloquent вставляет запись без идентификатора, база его подставляет, но **модель об этом не узнаёт**: она не перечитывает запись и возвращает мусор вместо ключа. В тестах это выглядело так, что два разных пользователя имеют одинаковый пустой идентификатор, а поиск по ключу сравнивал uuid с числом 19.

Правильно держать оба механизма:

- **`HasUuids` в модели** — в Laravel 13 он отдаёт `Str::uuid7()`, то есть модель проставляет ключ сама и сразу его знает;
- **значение по умолчанию в базе** — страховка для вставок мимо Eloquent: миграцией, скриптом, руками в psql.

Конфликта нет: если модель передала ключ, значение по умолчанию не применяется.

Урок шире одного случая: **«источник правды должен быть один» — не всегда верно.** Здесь два генератора решают две разные задачи, и удаление любого ломает свой сценарий. См. [[postgres-18-daet-uuidv7-bez-rasshirenij]].
