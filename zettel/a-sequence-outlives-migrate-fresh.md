# A standalone sequence outlives migrate:fresh

`migrate:fresh` drops tables. A sequence created with `create sequence`
is not a table, so it survives — and the next `migrate:fresh` dies on
"relation activity_log_seq already exists".

Nothing in the app is wrong at that point; the database is simply holding
an object no migration believes it created.

The fix is to let the column own the sequence:

    alter table activity_log add column seq bigint generated by default as identity

An identity column's sequence is dropped with the column and with the
table. Any place that needs a counter should prefer identity over a
free-standing sequence for that reason alone.
