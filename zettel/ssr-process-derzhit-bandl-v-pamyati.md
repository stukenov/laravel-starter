# Процесс SSR держит бандл в памяти — после сборки его надо перезапускать

Правил компонент, пересобирал `npm run build:ssr`, открывал страницу — изменений нет. Проверил файл: правка на месте. Проверил ответ сервера: там **старый** класс.

Причина простая и обидная: `node bootstrap/ssr/app.js` загружает бандл при старте и держит его в памяти. Пересборка меняет файл на диске, но работающий процесс об этом не узнаёт.

Потерял на этом три ложные проверки: дважды «починил» то, что и так было починено, и один раз завёл лишний токен, решив, что предыдущее решение не сработало.

Правило: **`npm run build:ssr` всегда в паре с перезапуском процесса SSR.**

    npm run build:ssr && pkill -f 'bootstrap/ssr' && node bootstrap/ssr/app.js &

В разработке этой проблемы нет — там рендерингом занимается dev-сервер Vite, а он подхватывает изменения сам. Ловушка срабатывает именно при проверке продового пути, то есть в самый неудобный момент.

Отсюда же следствие для прода: после каждого деплоя процесс SSR обязан перезапускаться, иначе сайт продолжит отдавать предыдущую версию интерфейса при уже обновлённом бэкенде. См. [[ssr-v-inertia-3-nastraivaet-plagin]].
