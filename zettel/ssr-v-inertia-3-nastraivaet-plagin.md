# SSR в Inertia 3 настраивает плагин, а не разработчик

План требовал написать `resources/js/ssr.tsx` с вызовом `createServer` и подключить его в `vite.config.ts`. Проверка показала, что это подход из Inertia 2, и в третьей версии он не нужен.

Плагин `@inertiajs/vite` делает три вещи сам:

- **находит точку входа** — годится обычный `app.tsx`, отдельный файл не требуется;
- **вшивает серверный бутстрап** прямо в собранный бандл;
- **в разработке рендерит через собственный dev-сервер** — Laravel шлёт данные страницы на `/__inertia_ssr`, отдельный процесс Node поднимать не надо.

Реально потребовалось два изменения в `config/inertia.php`: раскомментировать путь до бандла и исправить его имя.

Вот это второе и есть главное. Плагин собирает **`bootstrap/ssr/app.js`**, а не `ssr.mjs` из документации Inertia 2. Ошибка в имени **тихая**: приложение работает, страницы открываются, но приходят пустым контейнером без разметки. Ни ошибки в логах, ни падения — просто SSR молча не работает.

Поэтому тест проверяет не «файл настроен», а совпадение пути с тем, что действительно порождает сборка. См. [[proverka-dolzhna-lovit-tihie-polomki]].
