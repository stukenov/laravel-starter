# timestamptz работает правильно только при UTC на соединении

Решение «все даты в `timestamptz`» выглядело самодостаточным. Оказалось, у него есть скрытое условие, без которого оно даёт обратный эффект.

Механизм такой:

1. PHP отдаёт дату строкой **без смещения** — `2026-07-27 09:48:50`.
2. Postgres трактует такую строку в зоне **своей сессии**.
3. Postgres.app по умолчанию берёт зону системы — у меня `Asia/Almaty`.
4. Момент, задуманный как 09:48 UTC, сохраняется как 04:48 UTC.

Время уехало на пять часов назад. Приложение в UTC, колонка `timestamptz`, всё «правильно» — а момент неверный.

Проявилось это самым невнятным способом: токены сброса пароля рождались уже просроченными, и пользователь видел «This password reset token is invalid». Связи с часовыми поясами в этой ошибке нет никакой.

Лечится одной строкой — `'timezone' => 'UTC'` в настройках соединения `pgsql`. Коннектор Laravel выполняет `set time zone` при подключении.

Общий урок: **`timestamptz` спасает от потери смещения, но не от неверной его подстановки.** Оба конца — приложение и соединение — должны быть в UTC. Закреплено двумя тестами: один проверяет зону соединения, второй записывает момент и читает обратно, сравнивая с исходным. См. [[vremya-hranim-v-utc-pokazyvaem-v-zone-polzovatelya]].
